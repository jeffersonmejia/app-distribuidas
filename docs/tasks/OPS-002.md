# OPS-002 — Ejecución reproducible y seguridad del entorno

Issue: [#39](https://github.com/jeffersonmejia/app-distribuidas/issues/39) · Responsable: Jefferson (`jeffersonmejia`)

## Lógica y fuentes

- Entorno local: `docker/compose.yml` provee PostgreSQL y `docker/compose.sonarqube.yml` el servicio opcional local. Documentar comandos PowerShell, healthchecks, volúmenes y recuperación sin exponer secretos.
- Backend/frontend: documentar build y verificaciones existentes sin afirmar que tests omitidos por los Dockerfiles/workflows se ejecutaron.
- Azure: el proveedor ya está elegido e implementado como Terraform en `infra/` (PostgreSQL Flexible Server, ACI, ACR y OIDC). No describir el despliegue como agnóstico de proveedor ni replicar recursos manualmente.
- El state remoto requiere el bootstrap indicado en `infra/README.md`; revisar su costo antes de crearlo. No ejecutar `terraform apply` como parte de la reproducción local.
- Secretos de runtime, migración y administrador permanecen separados; solo `.env.example` se versiona. Ningún valor real se copia a docs o logs.

## Corrección necesaria a la issue

La frase actual “no asumir proveedor de despliegue” contradice el Terraform y `infra/README.md`. El alcance correcto es reproducir localmente y documentar el despliegue Azure ya existente, sin agregar otro proveedor.

## Criterios

Una copia limpia puede seguir instrucciones de desarrollo; variables de ejemplo son placeholders; recovery y límites/costos de Azure se documentan; `terraform plan` y `apply` se distinguen explícitamente.
