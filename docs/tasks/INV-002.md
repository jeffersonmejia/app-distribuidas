# INV-002 — Contrato de movimientos de inventario

Issue: [#6](https://github.com/jeffersonmejia/app-distribuidas/issues/6) · Responsable: Sahid (`Sahid-B`)

## Lógica confirmada

- Inventory publica la API que consume POS; POS no lee tablas, entidades ni repositorios de Inventory.
- El contrato distingue entradas, salidas y reservas, y transporta identificadores de producto como datos, no como autorización.
- Toda operación recibe el contexto tenant/actor validado por `tenancy`; fallos de validación o de disponibilidad no dejan escrituras parciales.

## Entrega

Documentar solicitudes, respuestas, errores y límites transaccionales del contrato público en Inventory. La tarea puede coordinar el contrato requerido por POS, pero no modifica archivos del módulo POS.

## Decisiones pendientes de contrato

Precisar cuándo una reserva se crea, confirma, libera o expira; cómo se representa la cantidad y su unidad; y qué clave garantiza idempotencia de reintentos. Acordar también qué error recibe POS cuando no hay disponibilidad. No definir esas reglas mediante supuestos locales.
