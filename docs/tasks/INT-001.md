# INT-001 — Integración y construcción completa

Issue: [#36](https://github.com/jeffersonmejia/app-distribuidas/issues/36) · Responsable: Jefferson (`jeffersonmejia`)

## Secuencia de integración

1. Integrar por PR a `develop` solo después de resolver las dependencias de feature indicadas en el Project.
2. Verificar build y checks de backend/frontend sobre el estado integrado, no sobre ramas aisladas.
3. Validar límites Feature-First: APIs públicas, sin acceso cruzado a entidades/repositorios, sin ciclos.
4. Aplicar migraciones desde una base vacía y comprobar que Hibernate valida el esquema.
5. Comparar rutas, DTOs, errores y permisos entre UI y APIs.

## Infraestructura como código

La configuración de Azure está en `infra/` y el workflow `Deploy develop to Azure` consume esos módulos. La integración verifica que sus cambios y dependencias sigan coherentes; no ejecuta `terraform apply` manual ni sustituye el workflow autorizado. Cambios de documentación no son deployment.

## Criterio de cierre

Builds correctos, reglas de calidad de `docs/quality.md`, migraciones y contratos compatibles. No cerrar la tarea si quedan conflictos de integración, fallos de aislamiento o decisiones de negocio sin especificación.
