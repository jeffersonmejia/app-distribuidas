# INV-003 — Movimientos y disponibilidad

Issue: [#29](https://github.com/jeffersonmejia/app-distribuidas/issues/29) · Responsable: Sahid (`Sahid-B`)

## Lógica

Implementar exactamente las entradas, salidas, reservas y consulta de disponibilidad que queden definidas en INV-001/INV-002. Cada movimiento se asocia al tenant del contexto validado y conserva trazabilidad. Las escrituras que cambian una cantidad se ejecutan en una transacción y protegen el saldo de inconsistencias; un rechazo no guarda una parte del movimiento.

## Integración

Inventory expone sus operaciones en `inventory.api`. POS consume esa API dentro del límite transaccional acordado; nunca consulta repositorios de Inventory. Toda tabla de negocio usa UUID, `tenant_id NOT NULL`, constraints tenant-scoped, migración Flyway y RLS fail-closed.

## Validación

Probar disponibilidad, cada tipo de movimiento, rollback y errores con PostgreSQL y el rol runtime definido. La cantidad no puede producir disponibilidad negativa si el contrato de INV-002 confirma esa regla. El contrato debe cerrar antes de implementar el comportamiento que depende de reservas.

## Dependencias

TEN-001 está completada. INV-001 e INV-002 son las dependencias actuales; POS-002 depende de esta feature.
