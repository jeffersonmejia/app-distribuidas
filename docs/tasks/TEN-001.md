# TEN-001 — Implementar tenants, membresías y contexto por solicitud

Issue: [#28](https://github.com/jeffersonmejia/app-distribuidas/issues/28) · Responsable: @jeffersonmejia · Área: Multitenancy

## Objetivo

Implementar ciclo tenant/membresía y contexto validado con persistencia Code First, RLS y migraciones.

## Instrucciones

1. Revisa el alcance aprobado en la Issue y las referencias del repositorio antes de modificar archivos.
2. Implementa únicamente lo necesario para cumplir los criterios de aceptación de esta tarea.
3. Mantén los cambios dentro de las rutas indicadas y coordina cualquier cambio de alcance antes de ejecutarlo.
4. Actualiza la documentación relacionada y deja evidencia verificable en la Issue o en el entregable correspondiente.

## Criterios de aceptación

- Validar membresía activa y permisos antes del acceso a datos.
- Propagar contexto explícito sin reutilizarlo entre solicitudes.
- Tablas tenant-scoped usan tenant_id NOT NULL y constraints tenant-scoped; tenant es una excepción global documentada.
- RLS falla cerrada; runtime no es superusuario, propietario de tablas ni BYPASSRLS.
- Pruebas PostgreSQL cubren acceso cruzado, falta de contexto, rollback y limpieza del contexto.
