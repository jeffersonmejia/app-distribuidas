# QA-003 — Integración y aislamiento multitenant

Issue: [#37](https://github.com/jeffersonmejia/app-distribuidas/issues/37) · Responsable: Jennifer (`Jntorres2001`)

## Casos obligatorios

- El tenant A no puede leer ni modificar registros del tenant B.
- Sin actor, membresía activa, permiso o contexto de transacción no se accede a datos tenant-scoped.
- Escrituras con tenant distinto al contexto y referencias entre tenants fallan cerradas.
- El rol de runtime de PostgreSQL no es superusuario, propietario privilegiado ni `BYPASSRLS`.
- Confirmar que el contexto de tenant se limpia al completar o revertir la transacción.

## Ejecución

Usar los flujos y datos sintéticos de cada feature implementada. No emplear identidades, datos reales ni tenant de producción. Registrar evidencia, resultado y owner para cada defecto. Los criterios de `docs/multitenancy.md` son la fuente normativa.

## Dependencia

TEN-001 está completada. INT-001 es la dependencia de integración; revisiones independientes de código implementado pueden hacerse antes, pero no sustituyen esta aceptación integrada.
