# SEC-001-H3 — Corregir la excepción CSRF de rutas CRM

Issue: [#202](https://github.com/jeffersonmejia/app-distribuidas/issues/202) · Hallazgo padre: [SEC-001 #40](https://github.com/jeffersonmejia/app-distribuidas/issues/40)

**Responsable:** Bruce (`BruceRodri`) · **Revisión:** Esteban/Larco (`EMLarco`) · **Estado:** Todo, corrección inmediata; sin bloqueadores.

## 1. Contexto y evidencia

El análisis local de SonarQube de QA-005 detectó la regla `Make sure disabling Spring Security's CSRF protection is safe here` con severidad Security High en `backend/src/main/java/com/erp/features/identity/infrastructure/security/SecurityConfiguration.java:25`.

La línea configura `csrf.ignoringRequestMatchers("/api/v1/crm/customers", "/api/v1/crm/customers/**")`. La cadena aplica `SessionCreationPolicy.STATELESS`, deshabilita HTTP Basic y form login y requiere autenticación JWT para todas las solicitudes. El registro anterior de SEC-001-H3 la describió como redundante, pero faltaba evidencia de la configuración efectiva y una corrección verificable. El hallazgo se prioriza para atención inmediata; la severidad final se actualizará después de la revisión manual, sin afirmar que el informe por sí solo demuestra una explotación.

`git blame` atribuye la línea al commit [810a1de](https://github.com/jeffersonmejia/app-distribuidas/commit/810a1de1055d60eec8f9c0358b34a15bbe1bb31b), de Bruce, integrado posteriormente por el PR #61. Jennifer es responsable del informe QA-005; Bruce es responsable de corregir su cambio.

## 2. Objetivo

Resolver el hallazgo en la cadena de seguridad real y dejar evidencia reproducible de que las rutas CRM siguen requiriendo JWT y que la protección CSRF está configurada de forma coherente con la autenticación efectiva.

## 3. Alcance

### Incluido

- Inspeccionar la versión efectiva de Spring Security y el orden/comportamiento de filtros para solicitudes autenticadas con Bearer.
- Eliminar la exclusión de rutas CRM si la API Bearer funciona sin ella y las pruebas confirman el comportamiento esperado.
- Si una excepción es estrictamente necesaria, limitarla al mecanismo Bearer demostrado y documentar por qué un navegador no puede autenticar estas rutas mediante cookies o sesión.
- Añadir o ajustar pruebas de seguridad/integración para acceso autenticado, acceso no autenticado, métodos de escritura y autorización existente.
- Registrar los comandos y resultados reales, actualizar `docs/tasks/SEC-001.md` y solicitar revisión acotada a Larco.

### Fuera de alcance

- Desactivar CSRF globalmente.
- Habilitar autenticación basada en cookies/sesión, HTTP Basic o form login.
- Cambiar autenticación JWT, permisos, contexto tenant, RLS, contratos de API o lógica de negocio CRM.
- Ampliar la tarea a otros hallazgos Sonar o hacer una nueva auditoría general.
