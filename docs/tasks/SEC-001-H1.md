## 10. Registro de corrección y cierre

La corrección incorpora validación en los casos de uso y la migración `V20261123_001__limit_approved_text_fields.sql`. Conserva las columnas `TEXT` y agrega ocho constraints `NOT VALID`; no modifica ni elimina filas. También se expresan los límites en los mapeos JPA. Las lecturas de filas heredadas siguen siendo posibles, pero PostgreSQL rechaza cualquier actualización de una fila que aún incumpla su constraint, incluso si se cambia otra columna.

Inventario: existen los ocho campos aprobados en cinco tablas; la descripción del proyecto es opcional. Otros textos como la descripción de tarea y el nombre y asunto de plantilla también usan `TEXT` sin máximos en esta tarea; quedan fuera de D1–D10 y requieren aprobación antes de añadirles límites.

Antes de validar las constraints, operación debe ejecutar los siguientes conteos con una identidad administrativa autorizada que pueda consultar todos los tenants, sin desactivar RLS ni usar la identidad runtime. Compartir únicamente los totales agregados. No validar las constraints ni truncar o borrar datos como parte de esta tarea; si hay incumplimientos, Jefferson debe acordar la remediación manual.

```sql
SELECT 'crm_customer.full_name' AS campo, count(*) AS filas FROM crm_customer WHERE char_length(full_name) > 200
UNION ALL SELECT 'projects_project.name', count(*) FROM projects_project WHERE char_length(name) > 150
UNION ALL SELECT 'projects_project.description', count(*) FROM projects_project WHERE char_length(description) > 2000
UNION ALL SELECT 'projects_task.title', count(*) FROM projects_task WHERE char_length(title) > 200
UNION ALL SELECT 'marketing_campaign.name', count(*) FROM marketing_campaign WHERE char_length(name) > 150
UNION ALL SELECT 'marketing_campaign.description', count(*) FROM marketing_campaign WHERE char_length(description) > 2000
UNION ALL SELECT 'marketing_template.html_body', count(*) FROM marketing_template WHERE char_length(html_body) > 100000
UNION ALL SELECT 'marketing_template.text_body', count(*) FROM marketing_template WHERE char_length(text_body) > 50000;
```

El backend rechaza entradas excesivas con los códigos de validación existentes y sin incluir los valores en la respuesta. Se cuenta la entrada completa, sin truncamiento, con `String.codePointCount`. Los ejemplos de pruebas son sintéticos.
