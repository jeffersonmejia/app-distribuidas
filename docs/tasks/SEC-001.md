### Controles verificados sin hallazgo

| Área (OWASP 2025) | Evidencia |
| --- | --- |
| A01 Control de acceso / tenant | Todos los casos de uso tenant-scoped pasan por `TenantAccess.execute`/`executeJoined` con permiso explícito y membresía `ACTIVE` validada en backend (`TenantAccessService`). `X-Tenant-ID` solo selecciona tenant; el rechazo es `AccessDeniedException` → 403 genérico. |
| A01 RLS | Todas las tablas de negocio tienen `tenant_id NOT NULL`, `ENABLE` + `FORCE ROW LEVEL SECURITY` y políticas `USING`/`WITH CHECK` con `NULLIF(current_setting('app.tenant_id', true), '')` (fallan cerradas). `app.tenant_id` se fija con `set_config(..., true)` dentro de la transacción y tras validar membresía. Runtime `erp_runtime` con `GRANT` mínimos por tabla/columna. |
| A07 Autenticación | JWT validado por issuer, audiencia y `sub` UUID (`SecurityConfiguration`); sesión `STATELESS`, sin `httpBasic` ni `formLogin`. |
| A05 Inyección | Consultas JPQL/SQL con parámetros enlazados; las concatenaciones solo unen fragmentos constantes (`JpaAccountingStore.list`, `ProductJpaRepository`). Plantillas de Marketing bloquean contenido activo (`Template.ACTIVE_CONTENT`) y el nombre de producto se escapa en `EmailLayout`. Frontend sin `dangerouslySetInnerHTML` ni `innerHTML`. |
| A02 Configuración | Swagger/OpenAPI desactivado salvo perfil `dev`; `ddl-auto=validate`; `open-in-view=false`; `logServerErrorDetail=false`. |
| A04 Criptografía / secretos | Secretos solo por variables de entorno o `secrets.*` de GitHub; `.env.example` con marcadores. `VITE_DEV_ACCESS_TOKEN` solo se lee bajo `import.meta.env.DEV`. |
| A03 Dependencias | `npm audit` (raíz y `frontend`): 0 vulnerabilidades. Spring Boot 3.5.6. |
| A09/A10 Registro y errores | Los `*ErrorHandler` devuelven `code` estable y mensaje genérico, sin detalles internos. El único log de negocio (`CampaignSendService`) registra UUIDs y la clase de excepción, sin correo ni mensaje del proveedor. |
| CI/CD | `pull_request_target` de `auto-develop.yml` no hace checkout ni ejecuta código del PR; `commitlint.yml` usa `pull_request` con permisos de lectura. |
